# AGENTS.md — ghostgit.nvim (vim-fugitive)

## Project identity

This is **vim-fugitive** by Tim Pope — a pure VimScript Git integration plugin. Despite the directory name `ghostgit.nvim`, this is **not a Neovim Lua plugin**; it is the original Vim plugin written in VimScript.

## Structure

- `plugin/fugitive.vim` — entry point; defines all `:G*` commands and the **public API** (functions prefixed with `Fugitive`)
- `autoload/fugitive.vim` — main implementation (~8400 lines); internal functions prefixed with `s:` or `fugitive#`
- `doc/fugitive.txt` — full help documentation (`:help fugitive`)
- `ftdetect/`, `ftplugin/`, `syntax/` — filetype detection and syntax for git/fugitive buffers

## Public API

All functions starting with `Fugitive` in `plugin/fugitive.vim` are the public API:
- `FugitiveGitDir([bufnr])` — returns the Git dir for a buffer
- `FugitiveReal(url)` — converts a `fugitive://` URL to a real filesystem path
- `FugitiveFind(spec)` — resolves a Fugitive object to a buffer name
- `FugitiveHead([truncate], [git_dir])` — returns current branch name
- `FugitiveExecute(args, [git_dir], [callback])` — runs Git asynchronously
- `FugitiveResult()` — returns result of the most recent `:Git` command
- `FugitiveDidChange([bufnr])` — triggers `FugitiveChanged` event
- `FugitiveConfig()`, `FugitiveConfigGet()`, `FugitiveConfigGetAll()`, `FugitiveConfigGetRegexp()` — config access
- `FugitiveRemoteUrl()`, `FugitiveRemote()` — remote URL parsing
- `FugitiveShellCommand()` — builds a Git command string
- `FugitiveStatusline()` — statusline indicator

**Do not call `fugitive#` functions directly** — they are internal and may change.

## Configuration variables

- `g:fugitive_no_maps` — set to 1 to disable automatic key mappings
- `g:fugitive_legacy_commands` — set to 1 to enable deprecated lowercase commands (`:Gstatus`, `:Gcommit`, etc.)
- `g:fugitive_dynamic_colors` — set to 0 to disable commit hash color highlighting

## Contributing conventions (from CONTRIBUTING.markdown)

- **Squash and force-push** any requested changes to a PR
- **Commit messages must follow proper style** — poorly written commit messages will be rejected
- **New configuration options require strong justification** — options add maintenance burden; prefer custom maps or autocommands
- The project is meticulous about maintaining clean, readable git history due to frequent bisection needs

## Development notes

- No build, test, lint, or typecheck infrastructure — pure VimScript
- No CI workflows in `.github/` (only `FUNDING.yml`)
- `doc/tags` is gitignored; generated by `vim -u NONE -c "helptags doc" -c q`
- Requires Vim 7.4+ (checked via `v:version`)
- Windows compatibility handled via `s:winshell()` and `s:WinShellEsc()`
- Plugin loader guard: `g:loaded_fugitive` prevents double-load
